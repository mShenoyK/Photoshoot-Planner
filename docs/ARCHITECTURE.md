# Architecture

Phase 1 combines Next.js App Router UI and versioned HTTP API, using the specification's simplification option. API orchestration lives in apps/web/lib/api.ts; shared Zod request contracts live in the @framecraft/shared workspace package. The database workspace owns the Prisma schema/migrations. Next.js explicitly transpiles shared TypeScript sources. Route handlers contain no business logic. A future Fastify service can reuse contracts without changing browser URLs.

Authenticated owner → API validation → repository → PostgreSQL/Prisma. Shoot inputs are typed JSON plus indexed owner, name, timestamps, soft deletion and revision columns. This deliberately avoids prematurely adding tables for unimplemented features. Migrations add normalized subject, consent, knowledge, plan and artifact tables in their milestones. Conditional updateMany enforces owner + revision atomically. Soft-deleted shoots are excluded everywhere.

Local DATA_MODE=mock uses serialized atomic file replacement under ignored .data. It persists accounts/briefs, is single-process only, and throws in production. PostgreSQL is the default and mandatory for deployment. No external AI services are needed for Phase 1.

Authentication scaffolding uses scrypt password hashes, eight-hour HS256 JWT sessions, HttpOnly SameSite cookies, Secure in production, origin checks on mutations, and per-email process-local throttling. Secrets must be supplied for production. This foundation is not an audited identity provider: email verification, account recovery, shared rate limiting, immediate session revocation and managed identity/Auth.js migration are production hardening tasks before public launch. JWTs contain only user IDs.

PWA manifest and network-first navigation fallback provide an offline notice; private pages and APIs are never cached. Editing offline is intentionally unavailable. Tailwind and semantic components share CSS design tokens, light/dark palettes, focus rings and reduced-motion support.

FC-007 introduces private S3 adapters; FC-012 introduces mockable text/vision/image/embedding interfaces; FC-013 introduces BullMQ/Redis worker and validated versioned plan JSON; FC-019 consumes that same JSON for all exporters. No placeholder generation endpoints claim those capabilities today. Original photos will be excluded from shareable exports. Citation integrity will be validated against real source records before marking any plan ready.

Wizard navigation guards cover both browser unload and Next.js link transitions while edits are unsaved. Canceling navigation preserves the current draft for retry.

FC-006–009 adds packages/shared/inputs contracts, input-repository.ts owner-scoped transactions, inputs-service.ts lifecycle rules, inputs-routes.ts HTTP dispatch, image-intake.ts bounded validation and object-store.ts local/S3 adapters. A per-shoot ShootWorkspace JSON aggregate intentionally keeps profiles, permission snapshots and media metadata in one consent/intake transaction; CameraKit is owner-indexed. See PHASE_2_SECURITY_REPORT.md for schema tradeoffs, lock semantics and orphan-cleanup limitations. Private bytes never live in a public directory or API JSON. Object URLs are never exposed; authenticated downloads preserve revocation checks.

FC-010–014 adds private owner-scoped KnowledgeWorkspace aggregates, an approved-summary KnowledgeSearchIndex with generated PostgreSQL tsvector/GIN index, and durable TaskJob records. Corpus and index writes share a User-row transaction. Search uses the same SQL transaction instead of opening a nested pool request. Review revisions remain monotonic across reindexing. Generation leases prevent source mutations during a plan request's retrieved snapshot. Strict source references and schema validation run before append-only plan persistence in the existing ShootWorkspace aggregate.

Six pnpm projects now include shared, database, knowledge and AI packages plus the web app/root. PDF extraction and private thumbnails execute on the server; originals stay under private knowledge/{owner}/{document}/ prefixes. API requests enqueue durable work; a separate BullMQ worker processes production tasks. The local single-process file backend provides an explicit in-process mock queue/recovery path. Interfaces cover text, vision, embeddings and original illustration providers, with clearly labeled deterministic mock implementations. No real model integration or native pgvector service is claimed. See PHASE_3_REPORT.md for data-model tradeoffs, privacy constraints and acceptance evidence.

FC-015–016 adds a pure coordinate-to-SVG renderer and deterministic lighting/wardrobe rules, validated by shared styling Zod contracts. Authenticated `/shoots/{id}/styling` requests use the existing owner-scoped Shoot row transaction. Append-only styling snapshots live beside plans in ShootWorkspace JSON, with their own revision and independent lighting/wardrobe input fingerprints. They deliberately do not mutate approved AI plan versions. The Lighting Lab and Wardrobe Stylist are linked from the brief and plan; future exporters must explicitly choose a plan version and styling revision. No additional migration, queue, AI key or image processing is needed for these bounded rules.

FC-017–022 adds a mockable structured PoseIllustrationProvider, original supported SVG primitives, strict subject/guardian validation, durable ILLUSTRATE/EXPORT jobs and immutable Artifact metadata inside ShootWorkspace. Exports consume explicit plan IDs and styling revisions; object writes use create-only keys and SHA-256 checks, and recovery never overwrites bytes. Generated objects reside in private per-shoot outputs; existing uploads already use per-shoot inputs. Download routes re-authorize owner/shoot membership and validate live source references. A short source lease prevents rights mutations during export/download; no original book images or user photos enter these providers/exporters. ZIP members are constructed from an allowlist and include a provenance/hash manifest. PDF rendering rasterizes only internally generated SVGs, never uploaded SVG or remote URLs. HTTP/request and worker event logging deliberately excludes bodies and credential-bearing URLs. See PHASE_5_REPORT.md for acceptance gaps, production constraints and evidence.
