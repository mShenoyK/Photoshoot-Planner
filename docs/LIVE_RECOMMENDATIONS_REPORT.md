# Private intake and live recommendation images

## Changes

Selecting a file enables **Upload privately**. If declarations or permission are missing, clicking it identifies the exact next step without sending an upload request or decoding the photo. Selecting a person exposes consent in the active intake form. Consent remains mandatory, including guardian authority for minors or unconfirmed ages; the server independently validates it before processing. A no-people reference can be explicitly declared without first guessing a different reference category. Existing selections survive consent refresh, and removed people are cleared from selection. Consent form IDs are unique when the same person appears in multiple workspace editors.

The production text factory now supports OpenAI structured shoot-plan generation, and Wardrobe Stylist can tailor unlocked outfit details with OpenAI while preserving candidate IDs, selected colors, user locks and server-managed citations. Subject/candidate counts and avoided garment colors are validated. Lighting settings and top/side SVG diagrams remain deterministic technical starting layouts, not simulated photographs or exposure guarantees.

Every new pose, lighting setup and outfit recommendation has an original-image response area. Explicit recommendation generation starts image requests when the provider is configured. Requests are limited to two concurrent submissions in the browser. Images are generated by the fixed OpenAI images endpoint, then reviewed in a separate vision request for exact declared subject count, age-band presentation, supported posing, scene and outfit agreement. A failed review is not published. PNG type, dimensions, byte count and decode limits are independently checked server-side, and metadata is stripped. This is an AI review aid, not a guarantee; users must inspect generated anatomy, safety, clothing and light interpretation.

The image generator receives saved textual guidance, scene/equipment context and approved textual observations, not uploaded photographs or source-book illustrations. People are fictional; this is not identity recreation, virtual try-on, measurement prediction or a guarantee of clothing fit. Baby/toddler wardrobe uses a people-free outfit flat lay; infant/toddler pose and lighting images require a declared adult caregiver. Photo-guided images require valid analysis consent plus separate generation permission for every reference participant. Knowledge-only guidance excludes photo observations as before.

The old face-marker and clothing-outline components are no longer used as recommendation images. Missing credentials, provider failures and rejected images show explicit states; no placeholder image is substituted. Production mock text, vision and legacy image generation are blocked. Local explicit mock modes remain available for automated tests and deterministic guidance; the live image area shows a configuration message instead of a fake image.

Generated PNGs use immutable `shoots/{workspace}/outputs/{job}/recommendation.png` keys and owner-authorized download routes. Metadata records exact guide/styling targets, input and guidance fingerprints, source review IDs, provider, independent review result and SHA-256. Unchanged guidance reuses its existing image across lock-only revisions; **Generate a new image** explicitly requests a new immutable output. Durable VISUAL jobs support failures/retries. The UI recovers a still-running inline job after an interrupted HTTP response instead of immediately starting another paid request. Expired inline jobs can be resumed. Per-job retries are bounded by the existing queue policy.

Downloads recheck ownership, current input permissions, live source citations and byte integrity. Consent/media removal deletes affected reference-derived images and queues physical cleanup if storage is unavailable. Workspace deletion also removes generated image objects. Private Files displays generated PNGs; ZIP exports include bounded JPEG copies with provider/review provenance and member hashes. Subject photographs, source PDFs, originals and consent records remain excluded.

## Render configuration

The user confirmed the OpenAI key is not configured yet and will add it securely in Render. Existing services must update these values explicitly; changing a Blueprint file alone does not change an already-created service:

```text
OPENAI_API_KEY=<enter securely in Render Environment>
AI_TEXT_PROVIDER=openai
AI_VISION_PROVIDER=openai
AI_IMAGE_PROVIDER=openai
AI_TEXT_MODEL=gpt-4.1
AI_VISION_MODEL=gpt-4.1-mini
AI_IMAGE_MODEL=gpt-image-1
```

The selected project/account must have model access and billing/quota. Keep the key server-side, never NEXT_PUBLIC or Git. Private S3 configuration remains required for production uploads and generated-image persistence, and configuration is checked before a paid image request. Both Render templates now select live providers and declare the secret binding. Database, auth and application-origin settings remain unchanged.

Inline jobs work with the current free-web setup, but an image generation plus review can be a long request. The UI recovers durable job status after an HTTP interruption. A BullMQ/Redis worker is recommended for sustained image workloads; use the existing optional worker template and shared private database/storage/provider settings. No paid worker or provider account is provisioned by this change.

They validate real request contracts, schema enforcement, provider authentication/rate/size failures, rejected image counts, stale inputs, owner isolation, immutable outputs, generation permission before provider invocation, cache reuse, explicit refresh and cleanup. These tests do not establish a paid model connection or semantic image quality.
