# FC-010–FC-014 — ingestion, retrieval and versioned planning

## Delivered workflow

1. Open the private knowledge library from the dashboard. Upload a Markdown or PDF source with title/author/edition, rights assessment, explicit ingestion permission, derived-use permission and optional private page/vision review permission. Production ingestion/review requires a server-configured administrator email; local mock users administer only their own private corpus.
2. A durable ingestion job fingerprints source bytes with SHA-256, deduplicates within the owner, stores the original privately, and extracts bounded chunks with source provenance. Markdown preserves heading paths, line ranges, tables and fenced text as untrusted content. PDF extraction preserves the actual PDF page index and reports pages without extractable text.
3. Review original paraphrased guidance before it can enter retrieval. Long copied phrases are rejected; this is a copying guard, not a legal rights assessment. An image-only page can be rendered as a private thumbnail, examined with a mock vision review aid, and given a manually written page-linked guidance card. Cards remain pending until approved. No scanned page or book illustration becomes a pose image, plan asset or export.
4. Search uses hard taxonomy filters (environment, age groups, subject-count range, topic), lexical ranking and optional cosine-vector reranking. PostgreSQL has a generated tsvector/GIN index over approved summaries; local mode uses a BM25-style lexical scorer. Neither path indexes unreviewed raw passages for user-facing retrieval.
5. Generate a plan from the brief, manually stated subject profiles and equipment. The text adapter receives reviewed summaries, exact source references and normalized inputs; it never receives source PDFs, original chunks, thumbnails, photo assets, consent/guardian history or credentials. Current text output is deterministic mock guidance. Exact known profile IDs, citation provenance, shot links, duration and a narrow age-safety rule are checked before persistence.
6. Creative brief, pose titles/directions/rationale (API), shot descriptions/priorities/completion (API) and section locks can be edited through validated contracts. Every save/approval/regeneration appends a version. Historical versions are read-only in the UI. Regeneration updates only the selected unlocked section and checks the base version; locked/approved other sections and old versions are preserved. User-edited pose guidance loses automatic source references rather than falsely attributing new wording to a book.

## Source and rights boundaries

Original source objects use `knowledge/{ownerId}/{documentId}/original.{md|pdf}` in the private adapter. No public original-source download route exists. Private thumbnails require an authenticated owner/admin, explicit private-review permission and an actual extracted PDF page number. They use no-store responses. Vision review additionally requires its own permission. Local mock vision explicitly performs no OCR or visual understanding; human review supplies the factual page summary. No real vision provider has been connected.

`allowOriginalDisplay` is server-controlled false. Unverified rights block initial ingestion. Only approved chunks with derived-use permission are eligible for retrieval. Permission withdrawal or source deletion removes eligibility and marks affected saved plans' citation status unavailable; approval is blocked until valid sources are restored or the plan is regenerated. Citation checks require real owner-scoped document/chunk IDs, title, exact page/line range and monotonically increasing review revision. Reindexing keeps deterministic chunk IDs while advancing revisions, so an old review cannot accidentally become current again. Active generation leases prevent concurrent source changes during generation.

Source excerpts and original images never appear in plan output. Reviewed paraphrases and provenance can appear in the owner's plan. Retrieval is not a guarantee that every generated direction is a statement from a book: source principles are displayed separately, and uncited/user-edited instructions are labeled. Reference material is never instruction authority. Zod rejects unknown provider fields; React renders plain text rather than unchecked model HTML.

## Queue and persistence behavior

Production uses BullMQ/Redis and a separate worker with concurrency 2, bounded attempts (3) and exponential backoff. Redis carries owner/job IDs, not private source contents. Durable task records carry status, progress, sanitized error codes and results. API requests use owner-scoped idempotency keys, retries preserve existing versions, and committed plan job IDs prevent duplicate versions after worker recovery. Ingestion job IDs likewise prevent replay from erasing reviewed guidance.

Local DATA_MODE=mock defaults to the in-process queue and an atomic private file store, with no Redis or paid API needed. It is a single-process development workflow. Queued/stale tasks can be recovered with `DATA_MODE=mock MOCK_DATA_FILE=apps/web/.data/framecraft.json STORAGE_LOCAL_DIR=apps/web/.data/private-objects MOCK_QUEUE_AUTO_RUN=false pnpm worker --once` while the web process is stopped; do not run a second mock-file writer alongside it. Production disallows the mock data/queue modes. Background jobs outlive neither process crashes nor lost connections by assumption: durable records and the worker/recovery instructions are required.

The private corpus is a PostgreSQL JSON aggregate locked on its owning User; its derived search index is maintained transactionally. TaskJob is owner-indexed with unique owner/kind/idempotency key. Shoot input and plan snapshots lock the owning Shoot. SQL values use bound parameters. These scoped aggregates are an explicit schema tradeoff, not separate normalized KnowledgeDocument/KnowledgeChunk/ShootPlan tables. A later scale migration can normalize them without changing the API contracts.

## Bounds and known limitations

- 10 MB source files, at most 150 PDF pages, 1,000 chunks/source, 4,000 chunks/private library and 20 active source documents. Markdown chunks target about 400 words with overlap and a character cap; source line ranges cover the containing section. PDF references use physical file page indices, not inferred printed page labels.
- Image-only PDFs require original human guidance cards. There is no automatic OCR/vision extraction claim. PDF.js and its canvas backend use matching native canvas versions; thumbnail canvases are bounded to roughly 600 × 840 and large embedded images are limited. Full production PDF malware isolation/scanning and load testing remain necessary.
- Optional embeddings currently use the mock hash-64 provider for reproducible vector mechanics. This is not a semantic-model quality claim. Vectors persist as JSON and cosine ranking is portable; native pgvector/ANN acceleration is not enabled or verified. Real embedding/text/vision adapters must be implemented/injected behind the exported interfaces; selecting unsupported provider IDs fails closed rather than silently pretending to call a vendor.
- Native generated Prisma-client, live Render PostgreSQL, real S3/IAM, external Redis/TLS and real AI-provider connectivity remain unverified. Existing Prisma engine/network prerequisites from earlier reports still apply. The local SQL suite substitutes a pg transport while executing the actual application SQL and migrations; it does not prove Prisma engine compatibility.
- Default source rights are private to one owner; there is no cross-account shared corpus, retailer integration, lighting/wardrobe generation, original pose images or exports in this milestone. No copyrighted user books were supplied/ingested by these tests, and no real subject photographs were used.
- Bounded job/corpus history needs operational retention, orphan cleanup, quotas, production admin-role hardening, backup policy and monitoring before public use. Source safety/rights review and photographer quality review remain human responsibilities. The deterministic unsafe-direction check is not a complete semantic safety classifier for future real models.
