# FC-017–022 implementation, security and release report

## Scope and delivered behavior

The app now has on-demand original schematic illustrations, immutable private output versions, a file library and Markdown/PDF/CSV/editable SVG/ZIP exports. GitHub Actions and Render web/worker templates are prepared, with explicit real-deployment checks. This is a local pilot candidate; a real Render release, paid provider integration and photographer pilot are separate acceptance gates.

- `packages/shared/src/artifacts.ts` defines strict requests, artifact metadata and provider figure schemas. `packages/ai/src/illustration.ts` adds a mockable structured PoseIllustrationProvider and deterministic original schematic fallback. No uploaded image or book illustration is supplied to it. Raw provider SVG/HTML is never trusted: validated coordinates become original local vector primitives. Exact subject IDs/count, supported seating and adult caregiver membership are checked before publication. Baby/toddler-only profiles cannot produce an unsupported illustration. These are support-and-spacing schematics, not photorealistic likenesses or exact limb/pose simulation; editorial/personalized image providers remain unavailable.
- `apps/web/lib/artifact-service.ts`, `artifact-routes.ts`, `pose-svg.ts` and `exporters.ts` create versioned output records through existing owner-scoped transactions. Explicit plan IDs and styling revisions avoid silently replacing approved work. Current inputs are rechecked before committing output so a mid-generation profile/age change cannot publish stale guidance. Durable ILLUSTRATE and EXPORT tasks share the worker's retry/idempotency contract and a 15-second illustration-provider deadline.
- Every output uses `shoots/{shootId}/outputs/{jobId}/...`, create-only local/S3 writes, immutable UUID metadata and SHA-256. Existing uploads already use private `shoots/{shootId}/inputs/...`. Downloads re-authorize the owner and route shoot, enforce hash integrity and use private/no-store attachments with CSP sandbox/nosniff. No raw storage keys appear in public metadata. A committed task replay returns its artifact; conflicting bytes are never overwritten. Shoot deletion blocks logical access and queues failed object deletions for an idempotent purge retry.
- ZIP members are generated from a strict allowlist: plan Markdown/PDF, shot-list CSV, selected lighting top/side SVG + editable coordinate JSON, already-requested original illustrations for that plan and manifest.json. All original uploads, subject photos, source books/pages/thumbnails, consent records and credentials are excluded. Manifest records plan/styling versions, actual source references, guidance provenance, member sizes/hashes and privacy exclusions. Source leases/live validation block new exports and downloads after a cited document is deleted or withdrawn.
- CSV fields are quoted and formula-leading values neutralized, including whitespace/control prefixes. Markdown escapes user HTML/markup. PDF uses bounded text wrapping/page layout and embeds only internally generated SVG diagrams/schematics via Sharp. Input/page limits constrain PDF work. Standard PDF font coverage is limited: unsupported glyphs are shown as U+ codes; UTF-8 Markdown/CSV preserve the original text.
- `/shoots/[id]/files` provides loading/error/empty/busy states, plan/styling selectors, explicit illustration generation, original schematic preview, export job status/retry and immutable download cards. Pose cards also have an on-demand illustration button. No generation runs just because a card/page is viewed.
- HTTP logs include generated request IDs, method/status/duration; worker logs include safe task IDs/kind/attempt/error codes. Bodies, query URLs, emails, prompts, database strings and tokens are omitted. `X-Request-ID` supports diagnosis. PostgreSQL readiness is separate from liveness and does not pretend to validate S3 or Redis.

No new paid credentials are needed for local mock workflows. See DEPLOYMENT.md for exact manual steps to connect GitHub, Render, PostgreSQL, Redis, private object storage and AI accounts. The current GitHub CLI token failed authentication and Render credentials were absent when checked; requesting reconnection is not proof credentials have been installed. Publication results must be confirmed separately by push output and actual-target smoke evidence. No API key or actual database password was added to source.

Storage and SQL transactions are not distributed: a crash after object creation but before metadata commit can leave an unreferenced private object. Create-only writes prevent replacement, but production needs a reconciliation/lifecycle policy. History aggregates need normalization/retention for large-scale use. Default shareable packages still contain participant labels and user-entered planning text, so the UI explicitly asks users to review them before sharing. No photographs are embedded by default, but the app does not promise that text is anonymous.

The controlled pilot rubric lives in PILOT_QA.md. No external deployment, remote CI success, real-user satisfaction metric or paid-provider connection is claimed without evidence.
