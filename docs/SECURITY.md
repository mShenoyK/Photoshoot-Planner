# Foundation security boundaries

Every shoot read/update/delete is owner-scoped using an authenticated session; cross-owner IDs return 404. Requests cannot set ownership. Revision conflicts return 409. Sessions are HttpOnly, SameSite=Lax, Secure under production, expire after eight hours and use a required production secret. Mutations require an exact configured Origin. Passwords use salted scrypt; API responses exclude hashes. Authentication throttling is per process and email; distributed throttling, session revocation, recovery and email verification remain launch blockers. Auth.js or managed authentication migration must be reviewed before a public pilot.

Never store personal photos, copyrighted source PDFs or actual credentials in Git. Originals belong in private ignored import directories until the private storage/consent milestone exists. FC-006–009 adds private photo intake only after valid declared-person consent; see PHASE_2_SECURITY_REPORT.md for authorization, decoder bounds, revocation and storage-outage behavior. No AI processing endpoint is enabled. Provider secrets never reach client modules. Production requires PostgreSQL; the serialized file demo is development-only and does not support multiple processes.

Private API responses and authenticated navigation must not enter service-worker caches. Offline mode displays only a static notice. Database backups, legal retention policy, durable reconciliation of pending/orphaned object deletions, audit logs, CSP rollout and production observability remain FC-021 work. Current health endpoint confirms liveness only.

## Knowledge and planning boundaries

The FC-010–014 private source pipeline requires assessed rights and explicit ingestion permission, owner-scopes all documents/chunks/jobs/plans, and permits thumbnails/vision review only with separate private-review permissions. Original pages are never plan images or export assets. Only approved original paraphrases with derived-use permission enter retrieval; raw source text remains untrusted reference material and is never model instruction authority. Citation validation checks actual current document/chunk IDs, page/line ranges and review revisions. Permission withdrawal/reindexing invalidate old citations rather than pretending they remain current.

Model output is strict Zod data, rendered as escaped text. Current generation uses manual profiles and reviewed summaries, never subject photographs or credentials. Provider error messages are not echoed as arbitrary job codes; exposed errors are sanitized/whitelisted. Production administration uses an explicit server email allowlist; mock-mode users administer only their own private corpus. The local Redis/SQL proof is not an external deployment or full production security audit. See PHASE_3_REPORT.md for limits, parser isolation, real-model quality and remaining operational controls.
