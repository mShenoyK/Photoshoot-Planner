# UI and reference-image workflow update

The requested redesign and functional changes are implemented as original FrameCraft UI and source code. The external Apple India site could not be fetched under this workspace's network policy; the design uses familiar spacious product typography, neutral surfaces, rounded cards, blue pill actions, translucent navigation and an original CSS lens graphic, without copying Apple logos, images or page assets.

## User-visible changes

- Responsive light/dark interface, a stronger landing/workspace hierarchy and consistent Overview / Reference images / Shoot plan / Posing guide / Lighting Lab / Wardrobe Stylist / Files navigation. Stale milestone messages claiming these features were unavailable have been removed from the active flow.
- Reference images are surfaced on all three planning tools, with authenticated previews, explicit analysis, editable review and confirmation. Confirmed reviews collapse to keep the plan readable. Mock mode never claims image detection; the OpenAI adapter is opt-in with secure configuration.
- Individual subject-photo analysis can describe uncertain visible proportions/body-shape impressions, approximate garment/background colors, fit considerations and three original outfits with rationale. Scene/pose references inform light direction and posing notes. Group photos do not attribute body observations to individual people. No personality, identity, health, inferred gender/ethnicity or precise measurements are requested from the model. Participant preferences and human corrections remain authoritative.
- A prominent Posing guide now includes original abstract face-spacing schematics, readable direction steps, safety/framing rationale, editable cards and explicit illustration/export actions. These schematics are not photographic likenesses or exact limb simulation; existing on-demand original schematic generation remains available.
- Lighting Lab uses confirmed key-side observations as context for its default geometry, keeps settings explicitly unmetered, and exposes numeric camera/key positions and heights as well as editable JSON/SVG. The specialized stacked-family recipe keeps its curated guide geometry and still requires on-location verification.
- Wardrobe uses confirmed per-person photo concepts and palettes while respecting color avoidance, manual fit/accessibility preferences and group locks. Basic hex hue-family checks prevent an avoided named color such as red from reappearing as a hex value. Explicitly locked looks survive re-review of a still-consented photo; revoked photo permission removes them from future rebalancing.
- Free/small production web deployments can run durable PostgreSQL jobs inline, so plans/exports no longer require a separate paid Redis worker by default. Already-completed responses update the UI immediately. The free web Blueprint is separate from the optional paid-worker template so it does not implicitly provision that service. Failed/abandoned jobs remain recoverable; larger workloads should use the existing BullMQ worker mode.

## Boundaries and privacy

Every identifiable person must have valid upload consent plus current analysis-purpose permission; minors require guardians. Permission checks run before image access or provider invocation. Derivative SHA-256 is verified, original metadata is stripped by the existing intake pipeline, and requests go only to the fixed OpenAI API URL. Model output is untrusted and strictly validated; the user must confirm/correct it before it influences tools. Provider calls are bounded and failures preserve saved work. Reference caches are purged with media/consent withdrawal. Previous private text plan/style history remains until the shoot is deleted; shareable exports still exclude photos by default.

Actual body appearance cannot be measured reliably from a single image. Clothing, lens perspective, cropping and lighting affect perceived proportions and colors. Model quality and fairness need human evaluation; this implementation does not assert objective body categories or guaranteed fit. It does not infer personality from appearance.

Real analysis requires AI_VISION_PROVIDER=openai, OPENAI_API_KEY and private S3-compatible storage. Default mock mode provides editable examples, not a local body detector. AI_TEXT_PROVIDER=mock remains deterministic text generation augmented by reviewed reference observations. Real OpenAI account access was not available; the vision HTTP contract was tested with synthetic responses, not a paid live call. The live Render host also remains unreachable from this sandbox's proxy. Deployment/account connections are not invented.
